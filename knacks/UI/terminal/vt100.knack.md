# VT100 Compatibility

## When To Load This Knack

Load this knack when a program, emulator, or terminfo entry claims "VT100"
compatibility and you need to reason about what that actually promises. This
is also the right starting point when a terminal bug report mentions cursor
movement, keypad modes, line drawing, autowrap, or a "works in xterm but not
in this emulator" mismatch.

## Mental Model

The DEC VT100 is the historical reference point for a huge amount of modern
terminal behavior, but it is not the whole story. It standardized a practical
subset of control-sequence behavior that many later terminals copied. Modern
emulators often support all VT100 behavior plus large amounts of VT220 and
later DEC behavior, xterm extensions, and Unicode-era features.

Treat "VT100-compatible" as "roughly the baseline control vocabulary" rather
than as a guarantee of perfect behavior. The original hardware had specific
limits and semantics:
- no modern color model;
- no Unicode;
- concrete rules around autowrap, scrolling margins, and origin mode;
- alternate keypad behavior;
- DEC Special Graphics line-drawing support; and
- optional VT52 compatibility mode.

If you need exact compatibility, read the DEC manuals and validate with a
terminal test suite. If you only need rough portability, use the VT100 label
as a hint about the floor rather than the ceiling.

## Important Behavior To Remember

Cursor movement and erasing:
- `CUU`, `CUD`, `CUF`, `CUB`, `CUP`, `ED`, and `EL` are part of the core
  working set.
- Scrolling regions and origin mode interact. Bugs often show up only after a
  program sets margins and then addresses the cursor.

Stateful DEC modes:
- `DECAWM` controls autowrap behavior.
- `DECOM` changes whether cursor addressing is relative to the full screen or
  to the current scrolling region.
- Keypad and cursor-key modes change what byte sequences keys transmit.

Character sets:
- VT100 line drawing is usually implemented through DEC Special Graphics, not
  through Unicode box-drawing characters.
- Many modern emulators translate or approximate these glyphs, but legacy
  applications may still switch character sets explicitly.

Compatibility modes:
- VT100 could emulate the older VT52 family.
- A "VT100" emulator may omit VT52 mode, or may implement it imperfectly.

## What Modern Emulators Usually Add

Modern emulators often exceed VT100 substantially:
- color and extended SGR handling;
- VT220 and later controls;
- mouse reporting;
- alternate-screen support;
- title setting and clipboard extensions; and
- UTF-8 and wide-character rendering.

That means two different errors are common:
- an application assumes only VT100 and leaves useful features on the table;
- an application assumes xterm-era behavior while advertising or selecting a
  stricter VT100 identity.

Keep the emulator identity, the `$TERM` value, and the actual escape traffic
aligned.

## Sharp Edges

Autowrap is frequently misunderstood. The right-edge behavior that real DEC
terminals used is not identical to the naive model many programmers imagine.
If wrapping, overwrite, or scrolling bugs appear only at the last column,
assume you are hitting terminal-specific semantics rather than a simple off-
by-one error in your application.

Do not use "VT100" as shorthand for "supports every escape sequence I found
in random blog posts." Many widely copied sequences are later DEC or xterm
extensions.

Do not assume line-drawing breakage is a font problem. It may be a character-
set selection problem, a bad terminfo entry, or a mismatch between DEC
Special Graphics expectations and a Unicode rendering path.

## Debugging Checklist

- Confirm what terminal identity the emulator advertises and what `$TERM`
  says.
- Check whether the failing sequence is truly VT100, later DEC, or xterm-
  specific.
- Reproduce with `vttest` when you need to separate emulator bugs from
  application bugs.
- Inspect keypad and cursor-key modes if function keys or arrows are wrong.
- Inspect wrapping and scrolling-region behavior when full-screen programs
  repaint incorrectly.
