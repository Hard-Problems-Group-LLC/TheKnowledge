Alembic SOP
===========

Technology
----------
- Name: Alembic
- Version policy: Keep Alembic aligned with the active SQLAlchemy major
  version.

Operational standards
---------------------
- Configuration baseline: Use Alembic for all relational schema changes and
  keep migration scripts in version control.
- Security constraints: Do not embed passwords in Alembic config. Feed the
  database URL through environment variables or runtime configuration.
- Observability and logging: Record migration application in deployment logs
  and review autogenerated migrations before they land.

Validation
----------
- Local verification steps: Run `alembic upgrade head` on a fresh database and
  on an existing development database before merge.
- CI verification steps: Fail CI if migrations cannot upgrade cleanly or if
  application models drift from migration history.
- Failure handling and rollback: Keep downgrade strategy explicit when the
  project requires it. Never hand-edit live tables as a substitute for a
  reviewed migration.

Maintenance
-----------
- Update cadence: Upgrade together with SQLAlchemy and revalidate migration
  templates afterward.
- Known risks: Unreviewed autogenerated diffs, irreversible data transforms,
  and hidden startup logic that mutates schema outside Alembic.
