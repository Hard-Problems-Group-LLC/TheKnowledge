Codex Sandbox Fallback for File-safe Static Analysis
===================================================

Scope
-----
Define the temporary workflow guidance for file-safe formatting and
static-analysis commands when a Codex sandbox exhibits the known multi-file
asyncio wakeup failure.

Problem Statement
-----------------
On this host, Codex's Linux sandbox can hang Black's multi-file execution
path, and similar file-targeted tools may hit the same runtime defect when
their work depends on asyncio wakeups from worker threads. TheKnowledge needs
a narrow, honest workaround so maintainers do not waste time retrying unsafe
or ineffective knobs such as `black -W 1`.

Requirements
------------
- Guidance must state that in a sandbox matched by
  `tool_execution_constraints.json`, Black should only run through
  `python scripts/run_tool_with_timeout.py black`, and that harness must run
  Black exactly one file at a time when more than one target file would
  otherwise be formatted.
- Guidance must still state that when another file-safe formatter or linter
  hangs inside a Codex sandbox on a multi-file run, maintainers should retry
  the explicit file list one file at a time.
- Guidance must state that `black -W 1` or similar worker-count flags are not
  sufficient to avoid the known multi-file hang.
- Guidance must keep the workaround narrow: use it for explicit file lists
  and other clearly file-safe modes, not as a blanket claim that every tool
  is safely serializable.
- Guidance must keep whole-repository validation as the final standard. The
  full required check suite still needs to run outside the affected sandbox or
  in CI before work is cleared.
- TheKnowledge's default `tool_execution_constraints.json` must record the
  current known-unsafe Codex sandbox case for Black's multi-file path. The
  current default entry may use Codex environment-variable matching as a
  heuristic, but that heuristic must live in the registry rather than as a
  hardcoded script rule.
- `scripts/run_quality_gate_cached.py` and
  `scripts/run_tool_with_timeout.py` must consult
  `tool_execution_constraints.json` instead of hardcoding a Codex sandbox
  environment variable for this workaround.
- When the current environment matches a registry entry that marks Black's
  multi-file path unsafe to parallelize, `scripts/run_quality_gate_cached.py`
  must run Black one file at a time for its explicit Python-file scope
  instead of delegating one multi-file Black invocation through the normal
  whole-repo command path.
- When the current environment matches a registry entry that marks Black's
  multi-file path unsafe to parallelize, `scripts/run_tool_with_timeout.py`
  must detect when a Black invocation would format more than one file and
  rerun those files one at a time through the same timeout harness instead of
  launching one multi-file Black process.
- The serial helper behavior must stay narrow: preserve the normal whole-repo
  quality-gate commands outside the affected sandbox and leave Ruff on its
  existing path until its file-safe scope is explicitly expanded.
- The serial helper behavior must preserve failure signaling by returning
  nonzero when any per-file Black invocation fails and by identifying the
  failing file clearly in the output.
- `AGENTS.md`, `templates/AGENTS-footer.md`, and
  `standards-and-practices/docs/development-workflow.txt` must document this
  temporary workaround and its registry-driven trigger.
- Documentation and helper tests must verify both the wording and the narrow
  Black-only serial-dispatch behavior.

Non-Goals
---------
- Proving that every third-party formatter or linter is file-safe.
- Replacing upstream Codex sandbox fixes.
- Lowering the repository's final validation requirements.
- Forcing one-file-at-a-time execution in unaffected shells or CI.
