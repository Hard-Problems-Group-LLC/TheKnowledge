Installation strategy
=====================

Use `scripts/install_prerequisites.sh` as the canonical bootstrap entry point.
The shell wrapper locates or installs Python 3, provisions `.venv` at the
repository root, upgrades packaging tools, and delegates system and Python
package installation to `scripts/install_prerequisites.py`.

Quick start
-----------

From the repository root:

```
./scripts/install_prerequisites.sh
```

The script defaults to installing project in editable mode with development
extras. Those extras pin the repository's default Black, Ruff, and pytest tool
versions exactly so local validation stays reproducible. Pass `--production`
through to the Python installer when you want to skip developer dependencies:

```
./scripts/install_prerequisites.sh -- --production
```

The `--` separator ensures arguments reach the Python installer unchanged.

Supported platforms
-------------------

- Rocky Linux 9.6 (dnf/yum)
- Fedora 43 (dnf)
- Ubuntu 24.x (apt)
- Linux Mint (apt)
- Debian stable/testing (apt)
- Modern macOS releases (Homebrew)

What the installer does
-----------------------

- Detects the platform and chooses an available package manager.
- Installs `python3`, `venv` tooling, `less`, and `git` using the native
  package manager (with `sudo` when required).
- Creates `.venv` if missing and upgrades `pip`, `setuptools`, and `wheel`.
- Installs the project in editable mode with optional pinned developer extras.
- Installs/updates managed git `pre-commit` and `pre-push` hook wrappers via
  `scripts/install_git_hooks.py`.

Notes and expectations
----------------------

- Run the installer from the repository root to ensure relative paths resolve
  correctly.
- If the host lacks `sudo`, run the script as a privileged user or install the
  required system packages manually.
- The Python logic supports a dry run for validation: `python scripts/
  install_prerequisites.py --dry-run`.
- Entropy-secret checks are wired into managed hooks:
  - `pre-commit` runs entropy checks.
  - `pre-push` runs cached quality-gate checks.
  See `standards-and-practices/docs/security/entropy-checks.txt` for details
  and manual run commands.
- Standardized git operation utilities are available after setup:
  - `python scripts/git_standard_commit_push.py -m "<subject>"`
    Lists files about to stage, asks whether to review them unless
    `--assume-reviewed` is passed or prompts were disabled earlier in the
    current shell session, prefers Meld review when available as the
    default visual review path, runs `git diff` before its own
    staging steps, runs `git diff --cached` before commit, uses
    `project-management/state/pending-commit-changes.txt`
    as commit body text when that file is nonblank, and clears the queue
    after a successful local commit. Use `--resume-review-prompts` to
    re-enable prompts for the current shell session.
  - `python scripts/git_veteran_pull.py`
  - Cache file used by push quality gate: `.git/project-quality-cache.json`
  - Runbook:
    `standards-and-practices/docs/security/git-tripwire-operations.txt`
- Consuming projects that update a TheKnowledge submodule should first fetch
  and briefly review the incoming upstream `trunk` delta in the submodule
  checkout, then adopt that reviewed version with
  `python TheKnowledge/scripts/git_veteran_pull.py`.
- After the submodule update, run
  `python TheKnowledge/scripts/report_managed_agents_drift.py --project-root`
  `. --knowledge-root TheKnowledge` to compare managed `AGENTS.md` sections
  with the updated templates. If drift is reported, rerun
  `python TheKnowledge/scripts/initial-setup.py --project-root .`
  `--knowledge-root TheKnowledge --force`, review `git diff`, and then stage
  the resulting submodule-pointer update plus only the intended project-file
  changes as one reviewable upgrade when they belong together.
- The managed starter for consuming projects also includes
  `requirements-dev.txt` and `scripts/dev_setup.py`, which install the same
  pinned Black, Ruff, and pytest toolchain by default unless a project adopts
  a stricter local bootstrap flow.
