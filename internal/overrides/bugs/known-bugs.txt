  2026-03-25T14:12:36-07:00
  Summary: Codex sandboxed Black hangs on multi-file runs because the
  sandboxed asyncio event loop does not wake reliably from worker-thread
  completion, and other file-targeted static-analysis tools may be exposed to
  the same runtime bug.
  Impact: sandboxed formatter and linter wrappers can wedge after file
  discovery, so AI maintenance work may need one-file-at-a-time tool
  invocations, escalated fallbacks, or external shells until the sandbox
  wakeup bug is fixed upstream.
  Current status: TheKnowledge now documents the fallback, records the known
  unsafe case in managed `tool_execution_constraints.json`, and serializes
  Black one file at a time in the cached quality gate when that registry
  entry matches, but the upstream sandbox wakeup defect remains open.
  Detailed record:
  `open/codex-sandbox-asyncio-wakeup-fails-for-multi-file-static-analysis.txt`

  2026-03-25T01:30:58-07:00
  Summary: Codex sandboxed commands fail on this EL9 host because the system
  `bubblewrap 0.6.3` binary does not support `--argv0`, and this Codex build
  appears to call `/usr/bin/bwrap` directly instead of honoring `PATH`.
  Impact: non-escalated `exec_command` and `apply_patch` paths fail with
  `bwrap: Unknown option --argv0`, forcing escalated-command fallbacks even
  after a newer user-local `bwrap` is installed earlier on `PATH`.
  Current status: local reproduction is fixed under `codex-cli
  0.117.0-alpha.17`, but this bug stays open until the same sandbox fix ships
  in a non-alpha/mainline Codex release.
  Detailed record: `open/bubblewrap-argv0-sandbox-incompatibility.txt`
